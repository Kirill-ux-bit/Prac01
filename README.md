. Команда dotnet build не пересобирает программу заново «с нуля» каждый раз. Она использует систему инкрементальной сборки, которая позволяет «вспомнить» предыдущие сборки и переиспользовать уже собранные артефакты, если исходный код и зависимости не изменились.

2. Если код не менялся с прошлого запуска, повторный dotnet build будет быстрее, чем первый, так как сборка использует кэшированные артефакты и не требует повторной компиляции неизмененных файлов. Это позволяет значительно сократить время сборки.

| Запуск | Условие | Время |
| ---: | ---: | ---: |
| 1 | чистая сборка (bin/obj удалены) | 0m3.367s |
| 2 | повторная сборка, код не менялся | 0m1.112s |
| 3 | сборка после изменения одной строки | 0m1.114s |


| Состояние | Что удалено | Время |
| ---: | ---: | ---: |
| А | ничего | 0m1.095s |
| В | только bin | 0m1.151s |
| C | bin и obj | 0m2.627s | 

3. Program.cs содержит исходный код, а файл проекта (.csproj) объясняет системе сборки, как именно его собрать.

4. При первой сборке .NET обычно выполняет много подготовительной работы: восстанавливает пакеты, создаёт служебные файлы и компилирует весь проект.
При повторной сборке система проверяет, изменились ли исходники и другие входные файлы. Если изменений нет, она может использовать уже созданные результаты и пропустить компиляцию. Кроме того, пакеты и файлы могут оставаться в кэше, а компилятор — уже работать в фоновом процессе.
Поэтому повторная сборка без изменений часто занимает гораздо меньше времени.


1. Первая сборка обычно медленнее: она восстанавливает зависимости и создаёт промежуточные файлы. Повторная может использовать сохранённые результаты.
2. bin содержит готовые файлы приложения, а obj — промежуточные данные сборки. Удаление obj обычно требует больше повторной работы.
3. Если не сохранять bin и obj, сборки обычно будут медленнее. Пакеты NuGet при этом могут остаться в отдельном кэше.
4. .csproj задаёт параметры проекта и сборки, например версию .NET, зависимости и настройки компиляции.
5. Изменение одного файла может не затронуть остальные проекты, но часто компилятор заново собирает весь изменённый проект.
6. bin и obj обычно не хранят в Git: это временные файлы, которые можно создать заново.
